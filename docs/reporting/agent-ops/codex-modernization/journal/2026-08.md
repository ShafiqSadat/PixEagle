# PixEagle Codex Modernization Journal - 2026-08

## 2026-08-26 - PXE-0159 Sparse Tracker Config Compatibility

- An older local config could select the newly shipped SparseFlow tracker but
  fail construction because its section did not contain `feature_strategy`.
- Runtime construction now uses the checked-in section defaults and overlays a
  sparse persisted/in-memory section. It does not rewrite local config; Config
  Sync or an explicit reset remains the persistence path.
- Focused factory/config, Phase 0, schema, syntax, and version-contract tests
  pass. The refreshed authenticated public lab reported v7.1.1 at commit
  `6ac924bc`, returned HTTP 200, switched from KCF to SparseFlow against the old
  config, then restored CSRT without a constructor or `feature_strategy` error.

  dlib skips and `1` deselected test. Dashboard `402`, schema `40/553`, Phase 0

- The unannotated supplied reel is only a smoke probe: the first 120 updates
  were usable, while the full run failed closed at the later scene transition.
  No identity, target-hardware, flight, field, or product-parity claim follows.

## 2026-08-25 - PXE-0158 Sparse Flow Tracker Research

## 2026-08-09 - PXE-0157 Browser-Lab Runtime Ownership Handoff

- Raspberry Pi evidence proved the canonical private UFW rules, then exposed a
  separate lifecycle conflict: a healthy managed service already held the
  runtime lease when the helper attempted a manual browser-lab launch.
- Browser-lab setup now resolves exact manual/service ownership before changing
  credentials, config, or firewall state. Interactive switching asks once;
  unattended switching is explicit and invalid or transitional ownership fails
  closed.
- Switching from the managed service stops only that owned runtime and preserves
  its boot auto-start policy. Focused lifecycle/firewall tests pass; target
  dashboard and NCNN export/load evidence remain pending.
- The generated SSH hint and installation authority now give one concise
  `make quick-browser-demo` reminder for router/LAN changes; address discovery
  and owned-UFW reconciliation remain in the existing helper.

## 2026-08-08 - PXE-0150 Private UFW CIDR Canonicalization

- Raspberry Pi browser-lab setup inferred `10.12.14.196/24`; UFW correctly
  normalized it to `10.12.14.0/24`, but exact textual verification rejected the
  valid owned rules and rolled them back.
- Trusted CIDRs are now parsed and canonicalized before UFW mutation, receipt
  publication, verification, and cleanup. A focused fake-UFW regression covers
  the exact host-bit case.
- Missing or inactive UFW remains non-fatal and no other firewall manager is
  mutated. Setup and troubleshooting guidance now give one rerun command for
  operators who enable UFW later.
- OpenCV 5 contrib adoption is separately tracked as deferred PXE-0156 with
  cross-platform tracker, streaming, ABI, and GStreamer acceptance gates.

## 2026-08-08 - PXE-0155 Raspberry Pi Full AI Bootstrap Handoff

- Raspberry Pi operator testing completed the Full AI installation but exposed
  that the profile did not install its separate NCNN/pnnx bundle. The trusted
  `.pt` model remained registered; only the requested NCNN export failed.
- Explicit Full AI setup now installs and verifies that bundle transactionally.
  Core remains the Enter-default profile, CUDA still uses `.pt` directly, and

  `python3` is missing. Unattended package mutation requires explicit policy and
  root or pre-authorized sudo.
- The optional SSH hint now reports configured authenticated network dashboard
  URLs and uses the canonical active-IPv4 discovery helper when no authority is
  saved. It never presents `0.0.0.0` as a browser destination.
- Local setup/model `349`, Phase 0 `73`, infrastructure-docs `31`, schema
  `39/518`, and static gates pass. Raspberry Pi export/load and refreshed SSH
  banner evidence remain operator gates; no inference benchmark, PX4, flight,
