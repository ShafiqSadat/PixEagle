## 2026-08-28 - PXE-0166 Shared Tracker Continuity

- Root cause isolated for the reported CSRT regression: command freshness
  became fail-closed on the first rejected frame, but the controller also
  started detector recovery on that same frame. This conflated safety with
  tracker-local continuity tolerance and caused recovery churn.
- Added one `BaseTracker` continuity contract for visual providers. Uncertain
  frames remain follower-ineligible and visible, while the configured failure
  threshold promotes the session to the existing bounded recovery path.
- Added controller compatibility fallback for older/custom outputs, focused
  regression coverage, and aligned tracker/recovery documentation. Hardware,
  camera, PX4, and annotated identity evidence remain pending. Focused,
  tracker-suite, schema, syntax, and Phase 0 gates pass; the integration-heavy
  `make test` target was stopped after 239 passing tests to avoid an excessive
  wait and reported no failure before interruption.

## 2026-08-27 - PXE-0164 Bounded-Latency Tracking UI

- The reported multi-second tracker-start delay was not tracker construction:
  SparseFlow initialized in tens of milliseconds and DaSiamRPN in about one
  tenth of a second. CPU-heavy processing instead made OpenCV file replay run
  below wall clock, while ordered WebSocket delivery had no rendered-frame
  feedback to bound network backlog.
- OpenCV-backed local files now discard only accumulated overdue frames in
  `REALTIME`. Deterministic replay and maximum-throughput modes preserve frame
  order, and GStreamer keeps its existing clocked leaky-appsink contract.
- The dashboard negotiates one-frame-in-flight WebSocket JPEG delivery and
  acknowledges exact render or decode failure. Legacy native and QGC clients
  remain compatible without negotiation.
- Replaced raw schema icon text with a bounded semantic icon renderer and added
  compact links to the classic-tracker, model, and follower references.
- A second strict appearance gate was not enabled for DaSiamRPN: comparative
  replay rejected more valid transition frames under simulated overload. A
  learned long-term/ReID provider remains separate deferred work instead of a
  scene-specific false-lock rule.

## 2026-08-26 - PXE-0160 Shared Classic Recovery

- Live loss evidence showed the estimator leaving the image and generating
  zero/undersized template-search crops for all five retries. The failure was
  in application-owned recovery, not SparseFlow's forward/backward gate.
- Added one pure target-size-aware search planner for all current and future
  `BaseTracker` visual providers: reliable prediction, last-measurement
  fallback, clipped edge search, expanding local regions, then bounded
  full-frame attempts.
- The detector now declares minimum search dimensions, rejects invalid regions
  before slicing, retains immutable plus trusted recent appearance views, and
  preserves the operator-selected identity across automatic reinitialization.
- Recovery proposals now carry typed, normalized candidate evidence. Duplicate
  multi-scale/template boxes are merged and a lookalike runner-up inside the
  configured score margin makes the attempt ambiguous without tracker mutation.
- Reinitialization moves tracker geometry but never learns from the tentative
  box; only the existing high-confidence measured-update path may refresh the
  trusted recent appearance view.
- Long-term tracking literature supports explicit distractor reasoning and
  conservative model updates. Learned ReID/tracklet association remains a
  separate deferred provider rather than ad hoc logic in the classic path.
- Predictions and candidates remain follower-ineligible until the tracker
  publishes a fresh measured output. Smart association and external gimbal
  providers retain their provider-specific recovery models.
